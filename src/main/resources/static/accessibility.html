Accessibility

This page says how accessible the payguard demo is, what was checked, and what was not.

What we aimed for

The screens are built to meet the Web Content Accessibility Guidelines (WCAG) 2.2, level AA. This is a demo built by one person, so there has been no independent audit. Nobody can honestly say "fully accessible" from the checks below, and this page does not.

What was checked

The browser tests in the ui-tests folder run on every change. They check:

  • An automated scan with axe-core of every screen, in light and in dark colour schemes, against the WCAG 2.0, 2.1 and 2.2 level A and AA rules. It reports no failures.
  • The whole payment journey, and the review journey, using only a keyboard. Every control can be reached and used, and the keyboard focus can be seen.
  • When one screen replaces another, keyboard focus moves to its main heading. When a form has mistakes, focus moves to a list of them, and each one links to its field.
  • No sideways scrolling on a screen 320 pixels wide, at text size 200%, or with wider spacing between letters, words and lines.
  • Every button, checkbox, radio button and text box is at least 24 by 24 pixels.
  • Each screen has a language, a different title, one main heading, headings in order, and labelled landmarks. Zooming is never blocked.
  • Every form field has a label, and hints and errors are tied to the field they belong to.
  • Nothing is told by colour alone. Every status has words as well.

What was not checked

  • Screen readers. The page uses the standard patterns for them (labelled fields, an error summary, a polite status message), but it has not been used with JAWS, NVDA, VoiceOver or TalkBack.
  • Voice control, switch devices, or screen magnifiers.
  • Any browser except Chromium.
  • Use by disabled people. No user research has been done.

Known problems

  • Signing in means pasting a long access token. That is allowed (pasting is never blocked), but it is not friendly. A real service would use its bank's own sign-in.
  • The review desk shows a payee's reference, not their name, because the API does not give a reviewer the name.
  • The list of held payments does not refresh by itself. Use "Refresh the list".
  • The list of a customer's payments is kept in the browser tab only, so it is lost on reload.

Tell us about a problem

If something here does not work for you, open an issue on the project's repository and say what you were trying to do and what you use to browse. Include the screen and, if you can, your browser and any assistive technology.
